03MOTION：唯一的架构冲突

冲突本质：PaperSharp 的整个产品承诺是「单帧、静态、确定性输出」（PNG/JPEG/WebP/SVG/PDF，同一输入恒定产物，财务级文档）。而 @keyframes/animation 是时间轴概念——一张静态图没有「第几帧」。清单里把 MOTION 与其余并列，是浏览器引擎的叙事，不是文档渲染器的。硬做会二选一：

方案 A · 跳过动画与现定位一致
维持 ROADMAP「明确不做动画」。清单里 MOTION 三项标为「不适用静态渲染器」。零成本，但不满足「都要支持」。
方案 B · 确定性取帧推荐
解析 @keyframes + animation（name/duration/delay/timing/iteration/fill），在给定时刻 t 求值动画属性→当普通样式渲染一帧。渲染 API 加可选 animationTime（默认取 fill-mode 终态）。Tailwind animate-* 在 tailwind.mjs 映射到标准 keyframes。输出仍单帧、仍确定性，契合图卡「定格某个动画瞬间」，成本 中–高。
方案 C · 动图输出
帧循环 + 编码 animated PNG/WebP/GIF/APNG。这是 takumi 主打的 OG 动画，等于把 PaperSharp 变成另一个产品：新编码器管线、PDF/SVG 无法承载、破坏「确定性单帧」卖点。成本 高，ROADMAP 已明确排除。

04需拍板决策清单

勾定范围后我按 Phase-1 直接落代码 + 补验收样例（assets/）+ 像素/语义回归。

D1MOTION 走哪个方案？
推荐 B（确定性取帧）——既「支持」动画 CSS，又不破坏静态/确定性内核。若你其实只想让清单「看起来全绿」而不在乎动画，则选 A 最省。
D2伪元素 content 做到多深？
Phase-1 建议 字符串 + attr() + 引号 + url() 图片；counter()/counters() 自动编号（图/表/章节号）对文档引擎价值最大但要多一个计数器求值子系统——要不要一并纳入 Phase-1？
D3三个缺口的取舍与顺序？
建议顺序 ①伪元素 → ②background-clip:text → ③backdrop-filter。②③主要服务图卡/营销线（m3 风），对发票/报表线价值有限——若你只关心文档，可先只做①。
D4是否顺带触发 M6（自研级联替换 AngleSharp）？
建议否。实测证明伪元素/:is/:where 都吃 AngleSharp 现成能力，本轮不依赖 M6，不必为加这几个特性去动级联内核（那是独立的高成本决策）。
