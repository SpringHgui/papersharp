One shot. 定格渲染的边界

本文只回答一个问题：PaperSharp 负责到哪一步为止。能力清单以 README 为准，差距与排期以 ROADMAP 为准，本文是两者的裁决依据。

定位：一次输入、一趟求解、一个定格产物。html + css (+ animationTime) → PNG · JPEG · WebP · ICO · SVG · 矢量 PDF。

三条承诺：①无事件、无交互、无时间轴——本引擎不实现「用户代理」中与用户有关的那一半；②渲染期不联网——资源只在调用方给定的 baseDir 与 data: URI 内解析，同一输入恒定产物（联网只有一处显式例外：字体预取 API，见 §1.1）；③无头进程内嵌——一个类库，不起子进程、不开调试端口、不依赖浏览器。

这三条不是省事的借口，而是尺子的来源：正因为产物定格且离线，"做完了没有"才能被钉成逐字节断言（见 §4），而不是"看起来挺像"。

§1不做清单

以下每一项都是裁决后的终态，不是待办。写在这里的用意是：任何人（含 AI）再提"顺手支持一下"，答案在此可查，不必重开讨论。

不做的能力连带不做的义务（真正的成本）与定位的冲突点
鼠标 / 键盘 / 焦点 / 滚动 hit-testing 树、焦点环与键盘导航、文本 selection 绘制层、光标与 IME 定位 需要事件循环：渲染不再是纯函数，输出取决于外部输入到达的顺序与时刻
滚动容器语义（overflow: auto / scroll） 滚动条几何与占位、滚动偏移、scroll-behavior、"当前滚到哪儿"参与出图 定格产物没有滚动位置 → 与 hidden 一样裁剪到 padding box（不画滚动条，也不为条子让位）。此为对外承诺，不是待办
增量布局失效与合成 脏矩形、保留式（retained）层树、合成器、滚动条几何 一次性求解的管线不需要缓存几何；引入失效即引入正确性黑洞
动画播放与多帧导出 时间轴推进本身、帧循环、APNG·GIF·animated WebP 编码管线。（单帧取帧已支持，见 §2，本行不否定它） PDF 与 SVG 静态路径无法承载时间轴；多帧等于换产品（ROADMAP 已排除）
:hover :active :focus :visited 用户状态位、状态伪类的样式重算 本引擎无用户状态来源，不承诺支持这四个伪类。Css/、Layout/ 内对它们零处理；AngleSharp 侧的匹配结果未实测，不作为本文依据

对照常见的「浏览器渲染引擎模块清单」，本表删掉两项（事件与交互、独立的"渲染树构建"阶段），补上四项（级联求值、匿名盒生成、分页模型、双输出后端），并把"HTML 解析"从自研改为外购。

§1.1 已定边界的，不进上面的表

已支持
判据：值被接受且产物确定，就是已支持——记在 README 能力表里，不算"不做"。下面几行都曾被误列进 §1，或仍挂在 ROADMAP 差距表上而实际行为早已定死。
项已定义的行为落点 / 待同步
position: fixed / sticky 值被接受，恒按 static 参与布局。Css/、Layout/ 内无 fixed/sticky 分支（CssSize.IsFixed 指"宽度是否定值"，同名不同事） README「定位」条已载。ROADMAP 差距表仍把它列为 gap（视口语义 · 中成本）——与已交付行为冲突，应改成"视口语义不做，静态降级已交付"或整行删除
overflow 裁剪 开裁剪的祖先把自己的 padding box 罩到整棵子树：矩形求交沿 BlockBox.Parent 链现算，长图 / 分页 / SVG 三条路径共用同一几何来源；祖先带圆角则按圆角矩形裁；裁剪盒不参与跨页碎片化（否则祖先与条目不在同一页坐标系） 落点：Layout/BlockBox.cs（OverflowClip）· Paint/VisualEffects.cs（ClipOverflow）· Painter / PagePainter / SvgWriter / Paginator。实测 AngleSharp 不认 clip·overlay·两值简写（computed 与 declared 双空）→ 走 UnsupportedProps 原文兜底。未做：BFC（见 ROADMAP「布局/BFC」行）
网络 src / url() 渲染期不联网：ImageLoader 遇 http(s):// 直接返回 null，不抓取、不重试、不产生超时不确定性，走图片自然回退 Layout/ImageLoader.cs:41。联网的唯一显式例外是字体预取 GoogleFonts.Fetch()（Css/GoogleFonts.cs:27）：拉取后改写为本地缓存路径（%LOCALAPPDATA%/PaperSharp/gfonts），失败即回缓存、再无则返回空串由渲染端回退——它是调用期 API，不在渲染路径上，与承诺 ② 不冲突
<script> 与外部 <link> 非视觉标签不成盒；不执行脚本、不为外部样式表发请求，输入始终是调用方给定的那一段字符串 属输入面契约，不是待办。需要动态内容由调用方先生成 HTML

§2看着像交互、实际必须保住的三项

砍 §1 时容易顺手砍掉它们，但三者都是渲染期一次算完的静态产物，与事件循环无关。

PDF 书签 · 链接注释 · 内部锚点 · 元数据

保住
从盒树收语义矩形（Layout/Pdf/PdfSemantic.cs，108 行），再在 PDF 尾部增量注入 outline / link annotation（PdfEnhancer.cs，343 行）。
  • 链接注释是 PDF 对象，不是 hit-testing——点击由阅读器实现，我们只负责把矩形和目的地写对。
  • 财务级文档卖点（目录、跳转、可追溯元数据），砍掉即降级为"一张印在 PDF 里的图"。

文本可选中、可搜索、可复制

保住
矢量 PDF 路径里文字是嵌入的 Type0/CID 字体 + ToUnicode 映射（配合构建期 fonttools 子集，GB2312 常用字整包 ~2.5 MB），不是位图字形。
  • 它的正确性判据是"复制出来粘进文本编辑器是不是原文"——纯静态可断言，与选择/光标无关。
  • 这是与"截图导出"路线的分水岭，也是最容易被误当成交互能力而被砍的一项。

@keyframes / animation

保住，但塌成一帧
解析全套（timing / iteration / direction / fill），渲染时传 animationTime（秒）→ 取该时刻的一帧，对 opacity / 颜色 / 长度 / 圆角 / 字号 / 定位偏移按帧插值。
  • 与定位自洽：调用方决定时刻，引擎仍是纯函数，逐字节确定（Css/Animation.cs 374 行）。
  • 边界：依赖 transform 的关键帧被解析但不生效（不做假变换），输出须与无动画逐字节一致——已有测试钉住。

§3管线与模块契约

主链七段 + 两段横切。括号内是落点文件；行数是当前规模，用来标示复杂度实际堆在哪里——级联、盒树/布局、文本三处吃掉了一多半，而常见清单把这三格写成了三行字。

主链（严格单向，一次求解） ① HTML 解析 → IDocument AngleSharp（外购，不重建） ② CSS 解析 + 级联求值 → ComputedStyle Css/StyleResolver.cs 927 · FlatCascade.cs 238 · CssValueParser.cs 616 · ComputedStyle.cs 222 ③ 盒树生成（含匿名盒） → BlockBox 树 Layout/LayoutBuilder.cs 1620 ④ 布局求解（measure/layout 双趟） → 定尺盒树 同上 + InlineLayout.cs 307 · FloatContext.cs 79 · CssSize.cs 56 ⑤ 分页 → 页序列 + 边距盒 Layout/Paginator.cs 420 · Css/PageSpec.cs 303 ⑥ 绘制顺序与落笔 → SKPicture/位图/SVG Paint/Painter.cs 160 · PagePainter.cs · BoxPainter.cs · Visual.cs 113 ⑦ 后端封装 → 字节流 Pdf/PdfEnhancer.cs 343 · Paint/SvgWriter.cs 395 横切（被 ②③④⑥ 共同调用，不是流水线上的一格） Ⓐ 文本子系统 Layout/FontManager.cs 223 · TextShaper.cs 239 · TextMeasurer.cs 236 · Paint/TextPainter.cs 213 Ⓑ 资源子系统 Layout/ImageLoader.cs 89 · Css/FontFaceParser.cs · GoogleFonts.cs · PseudoContent.cs 362 · CounterStyle.cs 131
模块契约（输入 → 输出）为什么不能与相邻模块合并
① HTML 解析 字符串 → 容错过、带隐式 html/body 的 IDocument HTML5 是带错误恢复的有限状态机，投入产出比极低——买不建。M6 只替换它的层叠，DOM 与选择器继续用 AngleSharp。
② 级联求值 声明 + 元素 → ComputedStyle（值处理模型走完 specified→computed→used，含初始值、继承、UA 表、简写展开、特异度与层叠次序） "解析 CSS" 与"算出样式"是两件事，中间隔着整个 Cascade。把它写成两格会漏掉最难的一半——M6 六步里 ①tokenizer、③属性元数据表、④值解析直连至今未做，只交付了 ②特异度+分桶。
③ 匿名盒生成 DOM+样式 → 盒树（块内裸文本→匿名块、table 内匿名行/格、inline 夹 block 的 split、::before/::after 各自成盒） 独立一格，因为它不属于解析也不属于布局，是两者之间的一次结构重写。漏做不报错，只表现为整体错位——是与真实浏览器逐盒对账时最容易假阳性的来源。
④ 布局求解 盒树 + 包含块 → 每个盒的 border/padding/content 矩形 此处有环：flex 交叉轴居中要先测子项、% 高度要等父项定尺、table 自动布局要两遍。所以是 measure/layout 双趟，不是一遍过。砍掉交互并不会让这一格变薄——它是数据依赖的循环，与事件无关。
⑤ 分页 定尺盒树 + @page → 页序列（跨页回流、break-*、orphans/widows、<thead> 重放、边距盒每页重绘） 面向屏幕的清单里没有这一格，对文档引擎它是核心。它反过来要求 ④ 可重入（同一段内容在不同页宽下重解）。
⑥ 绘制顺序 页 + 层叠上下文 → 落笔序列 不是独立阶段：要不要画由 ② 的 display/visibility 决定，画的次序是层叠上下文树 × 布局结果的函数。常见清单把它列成与布局并列的一格，会诱导多余的中间树。
⑦ 双后端 落笔序列 → 光栅（scale/DPI，Skia 直出）｜矢量（PDF 字体子集 + 语义尾注，SVG 录制） 两条路的正确性判据完全不同（像素 vs 文本层与结构）。清单只写"Skia 调用层"等于默认只出位图，那 PDF 卖点无从谈起。
Ⓐ 文本子系统 字符串 + 字体栈 → 字素簇 → shaping run → 行盒（基线、折行、回退） Skia 只给 glyph 与 metrics，不给 line breaker、不给 shaping、不给 bidi。HarfBuzz 连写、扩展字素、字形级字体回退都在这格。已知边界：完整 UAX#9 嵌套双向、国旗 emoji、shaped run 的 letter-spacing。

§4确定性：承诺的边界与取证现状

无交互 + 无网络换来最硬的一条 DoD：同输入 → 逐字节同产物。当前证据分三层，别混为一谈。

断言现状依据 / 缺口
位图路径逐字节确定 已钉测试 AnimationTests.cs:61 Same_time_is_deterministic（同一 animationTime 两次渲染字节一致）、:116（不同时刻互异 / 同刻一致）、ConcurrencyTests.cs:24·41·59（多线程与文档交错均等于串行基准）。
PDF 路径无时间破口 实测未见 取三份真实导出件（长文分页回归、加油站日报快照、Bootstrap Dashboard）检查：Info 字典内只有 /Producer（UTF-16BE "PaperSharp…"），无 CreationDate / ModDate，无 trailer /ID 数组；「长文分页回归」两份导出 md5 相同。
PDF 路径逐字节确定 未钉断言 上表的 md5 相同发生在同一浏览器会话内的两次导出，不构成跨进程证明；测试侧 PdfStructureTests.cs:23 目前只断言 %PDF- 头。待补：同一输入两次 RenderPdf 的字节比对。

承诺范围（精确措辞）：在同一版本的 PaperSharp、SkiaSharp / HarfBuzzSharp、fonttools 字体子集产物与 baseDir 资源树之下，同一 (html, css, animationTime, width/scale, pageSize, precomputed) 输入，任何线程、任何次序，输出逐字节相同。不承诺跨依赖版本或跨机器的字节相同（字体子集与 shaping 版本会变），那属于可复现性而非确定性。

§5待拍板

§1–§4 的裁决已定，以下是仍需拍板的执行细节。

D1PDF 的逐字节断言要不要现在补？
建议：补。一条 Fact 复用 Fixture.RenderPdf 连渲两次比 SequenceEqual，成本近乎零；不补则 §4 第三行永远停在"未见破口"而非"已钉住"，README 里"确定性输出"这句对外承诺就只覆盖位图。
D2状态伪类与未实现属性，静默忽略还是可诊断？
建议：保持静默忽略（渲染结果确定性优先），但把"不支持"清单写进 README 能力表，让它成为对外契约的一部分。反对意见是"报错更早发现问题"，代价是不认识的属性会中断整篇文档渲染，对导出真实网页快照的插件路径（扩展已把 overflow:hidden 近似成 clip-path、background-image:url() 合成 <img>）不可接受。
D3本文与 README / ROADMAP 的分工是否写死？
建议：写死并互相加链接——本文=边界裁决（为什么不做），README=能力表（做了什么），ROADMAP=排期（下一步做什么）。三处各答一个问题，任何一条能力从 ROADMAP 迁到本文 §1 时，三处同步改。
维护约定：本文只在边界变化时改（新增一项"永久不做"、或一项从"不做"迁回待办）。单个 CSS 属性的支持状态变更请改 README 能力表与 ROADMAP 差距表，不要往本文加内容。
